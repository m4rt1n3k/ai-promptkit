# ADR-0002: DEV|L maturity spiral over native Spec Kit

- Status: accepted
- Date: 2026-09-03

## Context

Applied research must evolve from a working engineering chain through a defensible scientific core into a scalable market application. Spec Kit supplies the Delivery loop, but maturity direction and real-world interpretation need an explicit outer lens. Parallel logs, personas and session workflows duplicated native authority.

## Decision

1. Use **DEV|L — Develop–Delivery Spiral** with native Spec Kit as the exclusive Delivery authority.
2. Begin every spiral turn with human maturity judgment and top-level agent selection.
3. Define Grade 1/Engineer as the minimal working chain, Grade 2/Scientist as the excellent defensible core solution, and Grade 3/Business as the scalable market-ready ecosystem.
4. Treat grades as repeatable and reversible descriptions, never acceptance gates or automatic promotion.
5. Let the chosen agent produce only a prompt for native `speckit.specify`.
6. Persist maturity, inherited evidence, requirements, design and work only in native `.specify/` and `specs/` artifacts.
7. Feed real-world application evidence into the next spiral turn.
8. Customize native templates only through one append-only preset; maintain no parallel command personas.
9. Reserve `takeover` for one-time Spec Kit incorporation into an existing codebase. Provide no repository-level session handoff.

## Consequences

- Evolution is explicit without a second artifact system.
- Each turn has one bounded Spec Kit feature and one selected maturity lens.
- Scientific excellence and market readiness require real evidence beyond Delivery convergence.
- Existing codebases gain a controlled path into Spec Kit; routine work stays entirely native.
